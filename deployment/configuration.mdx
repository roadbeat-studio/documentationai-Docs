## Overview

roadbeat Studio is configured primarily through **environment variables** set in a `.env` file or via your deployment platform. All configuration is validated on startup using Joi schemas — missing required variables cause the application to fail fast with a clear error message.

<Callout kind="info">
  In a source checkout, the API reads exactly **one** `.env` file: the one at the root of the `studio` workspace (copy `.env.example` there). A per-app `apps/api/.env` is not read. Real environment variables (Docker, CI) always take precedence over values from `.env`.
</Callout>

## Required Variables

These variables must be set for Studio to start:

| Variable | Description | Example |
|----------|-------------|---------|
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://user:pass@localhost:5432/studio` |
| `JWT_SECRET` | Secret key for signing JWT tokens (min 32 chars) | `your-secret-key-at-least-32-characters` |

## Database

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | — | PostgreSQL connection string |

Studio uses **Prisma** as its ORM. The database URL follows the format:

```
postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public
```

<Callout kind="tip">
  For production, enable connection pooling with PgBouncer or Prisma's built-in connection pool. Add `?connection_limit=10` to the DATABASE_URL.
</Callout>

## Redis

| Variable | Default | Description |
|----------|---------|-------------|
| `REDIS_HOST` | `localhost` | Redis server hostname |
| `REDIS_PORT` | `6379` | Redis server port |
| `REDIS_PASSWORD` | — | Redis password (optional) |
| `REDIS_DB` | `0` | Redis database number |

Redis is used for caching, session storage, and BullMQ job queues.

## Authentication

| Variable | Default | Description |
|----------|---------|-------------|
| `JWT_SECRET_CURRENT` | — | **Primary** secret for signing new JWT tokens |
| `JWT_SECRET_PREVIOUS` | — | **Previous** secret — tokens signed with this key are still accepted (for zero-downtime rotation) |
| `JWT_SECRET` | — | Legacy single-secret fallback (used if `JWT_SECRET_CURRENT` is not set) |
| `JWT_EXPIRATION` | `24h` | Access token lifetime |
| `JWT_REFRESH_EXPIRATION` | `7d` | Refresh token lifetime |

<Callout kind="tip">
  **Key rotation procedure:** To rotate JWT secrets without logging out all users:
  1. Copy the current `JWT_SECRET_CURRENT` value to `JWT_SECRET_PREVIOUS`
  2. Set `JWT_SECRET_CURRENT` to a new random string
  3. Restart the API — existing tokens are verified against both secrets
  4. After the access token lifetime (default 24h), all active tokens will use the new secret
  5. Remove `JWT_SECRET_PREVIOUS` on the next rotation cycle
</Callout>

## Mail

| Variable | Default | Description |
|----------|---------|-------------|
| `MAIL_TRANSPORT` | `log` | Mail transport: `smtp` or `log` (dev-only, prints to console) |
| `MAIL_FROM` | `noreply@localhost` | Sender address for outbound emails |
| `MAIL_BASE_URL` | `http://localhost:4200` | Base URL for links in email templates (e.g. password reset) |
| `SMTP_HOST` | — | SMTP server hostname (required when `MAIL_TRANSPORT=smtp`) |
| `SMTP_PORT` | `587` | SMTP server port |
| `SMTP_USER` | — | SMTP username |
| `SMTP_PASS` | — | SMTP password |

<Callout kind="info">
  When `MAIL_TRANSPORT=log` (the default), emails are printed to the server console instead of being sent. This is useful for local development — you can see password reset links in the logs without configuring an SMTP server.
</Callout>

<Callout kind="tip">
  For production, set `MAIL_TRANSPORT=smtp` and configure your SMTP credentials. Services like Postmark, SendGrid, Mailgun, or Amazon SES all work with standard SMTP settings.
</Callout>

## Content Types

| Variable | Default | Description |
|----------|---------|-------------|
| `CONTENT_SHAPE_MIGRATION` | on | At startup, Studio normalizes every content type not yet marked as storing its fields at their schema path (`x-studio-storage: schema_path/1`) and moves that type's existing content and version history to the storage paths. The pass is idempotent. Set `off` to skip it — e.g. when you run it as a separate deploy step |

## Consumer Features

| Variable | Default | Description |
|----------|---------|-------------|
| `CONTEXT_DIRECTORY_URL` | `http://localhost:3100` | Context Directory endpoint |
| `CONTEXT_DIRECTORY_TIMEOUT` | `10000` | CD request timeout in ms |
| `CONTEXT_DIRECTORY_SERVICE_KEY` | dev: `roadbeat-dev-cd-service-key` | Shared key Studio sends as `X-Service-Key` to the Context Directory's system-to-system endpoints (`POST /auth/register-or-link`). **Required in production** — there is no default there, and it must equal the Context Directory's `CD_SERVICE_KEY` |
| `FEDERATION_TIMEOUT_MS` | `5000` | Federated search timeout |
| `DISCOVER_DEBUG` | `false` | Development only: adds the raw Discovery Node requests (`_debug`) to consumer search responses, shown as a debug panel in Discover. Leave off in production |

<Callout kind="alert">
  The Context Directory refuses `register-or-link` without a valid service key (it fails closed), so consumer sign-up and account linking stop working on a production node that does not set `CONTEXT_DIRECTORY_SERVICE_KEY`. Set the same value on Studio and on the Context Directory.
</Callout>

## Pro / Plugins

| Variable | Default | Description |
|----------|---------|-------------|
| `ROADBEAT_LICENSE_KEY` | — | Ed25519-signed license JWT |
| `PLUGINS_DIR` | `./plugins` | Directory containing plugin packages |
| `PLUGIN_MIGRATIONS` | on | The API applies the SQL migrations of the discovered plugins at startup, before the plugin modules initialize. Set `off` if a deploy step applies them instead |
| `PLUGIN_BASE_MIGRATIONS_DIR` | `<PLUGINS_DIR>/../packages/plugin-base/migrations` | Location of the shared plugin-base migrations, which run before any plugin's own files |

See [Plugin System → Plugin database migrations](/plugins/overview#plugin-database-migrations) for how applied files are tracked.

### Pro plugin secrets

<Callout kind="alert">
  Each of these degrades **silently** when unset — the plugin still starts and works, just without the protection. Set all three that apply to the plugins you run.
</Callout>

| Variable | Plugin | Consequence if unset |
|----------|--------|----------------------|
| `PRO_SSO_SECRET_KEY` | pro-sso | IdP client secrets are stored **unencrypted**. Encryption becomes a logged no-op, so the plaintext sits in the database. A 64-hex-character key, or any passphrase (SHA-256 derived). |
| `PRO_AI_VAULT_KEK` | pro-ai | AI provider credentials fall back to an insecure development key — `GET /pro/ai/status` reports `vaultKeyMode: 'insecure-dev'`. Base64-encoded 32 bytes. The plugin refuses to start in production without it. |
| `AUDIT_PSEUDONYM_SECRET` | pro-audit | GDPR erasure pseudonyms are keyed by a value published in the source, so `erased-user-<hex>` is re-identifiable by anyone who can guess a user id — it is not anonymisation. Generate with `openssl rand -base64 32`. |

<Callout kind="info">
  `AUDIT_PSEUDONYM_SECRET` changes the pseudonym a given user maps to. Users erased before you set it keep their old pseudonym, so activity correlation does not carry across the change. Set it before going live if you can.
</Callout>

## Rate Limiting

| Variable | Default | Description |
|----------|---------|-------------|
| `THROTTLE_TTL` | `60000` | Rate limit window in ms |
| `THROTTLE_LIMIT` | `100` | Max requests per window per bucket (see below) |
| `LOGIN_THROTTLE_LOOPBACK_BYPASS` | `true` | Development only: with `NODE_ENV=development`, logins from this machine skip the 5-per-minute login limit so E2E runs and scripts can sign in repeatedly. Set `false` to keep the limit. Never applies outside `development` |

Each request is counted in exactly one bucket:

| Request | Bucket |
|---------|--------|
| Delivery API (API key) | `apikey:{keyId}` — one budget per key, using the key's own rate limit |
| Signed in (JWT) | `org:{orgId}:user:{userId}` — one budget per user |
| Anonymous, or an invalid/expired token | client IP |

<Callout kind="info">
  Rate limiting is **per user** for signed-in traffic. The global guard verifies the bearer token itself (with the current and previous JWT secret) before any controller runs, so several editors behind one NAT or office proxy no longer share a single budget — a page load in Studio makes 7–10 API calls. Forged, expired or malformed tokens count as anonymous and fall back to the IP bucket.
</Callout>

<Callout kind="tip">
  The loopback bypass checks the **socket** peer, not `req.ip`, and every `X-Forwarded-For`, `X-Real-IP` and `Forwarded` address must be loopback too. The `NODE_ENV` gate matters: behind a reverse proxy every production request arrives from a loopback peer.
</Callout>

## Backup & Restore (Optional)

See [Backup & Export](/guides/backup-and-export). Offsite S3 credentials fall
back to the asset `STORAGE_S3_*` credentials when their own are unset.

| Variable | Default | Description |
|----------|---------|-------------|
| `BACKUP_SCHEDULE_ENABLED` | `false` | Enable the daily scheduled backup of every org |
| `BACKUP_RETENTION_DAYS` | `30` | Prune backups (local + offsite + row) older than this. `0` = keep forever |
| `BACKUP_ENCRYPTION_KEY` | — | AES-256-GCM key (hex-64 or base64, 32 bytes). Empty = plaintext at rest |
| `BACKUP_S3_BUCKET` | — | S3-compatible offsite bucket. Empty = local-only (offsite disabled) |
| `BACKUP_S3_ENDPOINT` | `STORAGE_S3_ENDPOINT` | Offsite S3 endpoint |
| `BACKUP_S3_REGION` | `eu-central-1` | Offsite S3 region |
| `RESTORE_DRILL_ENABLED` | `true` | Weekly read-only restore-verification drill on the latest backup |

## Account Security (Optional)

| Variable | Default | Description |
|----------|---------|-------------|
| `LOCKOUT_AUTO_UNLOCK_MS` | `0` | If `> 0`, auto-unlock a locked account whose last failed attempt is older than this window. `0` = manual admin unlock only |
| `CAPTCHA_PROVIDER` | — | `turnstile` (Cloudflare) or `hcaptcha` to gate login & password-reset. Empty = disabled |
| `CAPTCHA_SECRET` | — | Secret for the selected captcha provider |
| `PASSWORD_MIN_LENGTH` | `8` | Minimum password length enforced on every entry point |
| `PASSWORD_REQUIRE_SYMBOL` | `false` | Require at least one symbol in passwords |
| `CE_AUDIT_RETENTION_DAYS` | `0` | Prune CE audit-log rows older than this. `0` = keep forever |

<Callout kind="tip">
  Secrets can be provided from a file instead of the environment by appending
  `_FILE` to the variable name (e.g. `METRICS_TOKEN_FILE`,
  `ERROR_TRACKING_DSN_FILE`, `CAPTCHA_SECRET_FILE`) — the standard pattern for
  Docker/Kubernetes secrets.
</Callout>

## Example .env File

```bash
# Database
DATABASE_URL=postgresql://studio:secretpassword@localhost:5432/roadbeat_studio

# Redis
REDIS_HOST=localhost
REDIS_PORT=6379

# Auth
JWT_SECRET_CURRENT=change-this-to-a-long-random-string-at-least-64-chars
# JWT_SECRET_PREVIOUS=old-secret-during-key-rotation
JWT_EXPIRATION=24h

# Search (optional)
MEILISEARCH_HOST=http://localhost:7700
MEILISEARCH_API_KEY=your-meili-master-key

# Storage
STORAGE_PROVIDER=local

# Publishing
SCHEMA_REGISTRY_URL=http://localhost:3200
DISCOVERY_NODE_URLS=http://localhost:3300
DISCOVERY_NODE_PUBLISHER_KEY=your-publisher-key

# Consumer
CONTEXT_DIRECTORY_URL=http://localhost:3100
# Required in production; must equal the Context Directory's CD_SERVICE_KEY
# CONTEXT_DIRECTORY_SERVICE_KEY=change-this-to-a-long-random-string

# Crash logging (optional)
# CRASH_LOG_FILE=/var/log/studio/api-crash.log

# Federation (optional — enables ActivityPub)
# FEDERATION_GATEWAY_URL=http://localhost:3500
# FED_ADMIN_TOKEN=change-this-to-a-long-random-token-at-least-64-chars

# Mail
MAIL_TRANSPORT=log
MAIL_FROM=noreply@localhost
MAIL_BASE_URL=http://localhost:4200
# SMTP_HOST=smtp.example.com
# SMTP_PORT=587
# SMTP_USER=your-smtp-user
# SMTP_PASS=your-smtp-password

# Server
PORT=3000
CORS_ORIGIN=http://localhost:4200
NODE_ENV=development
LOG_LEVEL=debug
LOG_PRETTY=true

# Observability (optional)
# METRICS_TOKEN=change-this-to-a-long-random-token
# OTEL_ENABLED=true
# OTEL_EXPORTER_OTLP_ENDPOINT=http://tempo:4318
# ERROR_TRACKING_DSN=https://<key>@glitchtip.example.eu/1

# Backup (optional)
# BACKUP_SCHEDULE_ENABLED=true
# BACKUP_RETENTION_DAYS=30
# BACKUP_ENCRYPTION_KEY=<hex-64-or-base64-32-byte-key>
# BACKUP_S3_BUCKET=studio-backups
```

## Production Checklist

<Callout kind="alert">
  Before deploying to production, ensure these items are addressed:
</Callout>

- [ ] `JWT_SECRET_CURRENT` is a unique, random string (min 64 chars)
- [ ] Enable MFA for all admin accounts (TOTP via authenticator app)
- [ ] `DATABASE_URL` uses a strong password
- [ ] `NODE_ENV=production` is set
- [ ] `LOG_PRETTY=false` for structured JSON logs
- [ ] `CORS_ORIGIN` is set to your actual domain
- [ ] `STORAGE_PROVIDER=s3` with proper credentials
- [ ] HTTPS is configured (via Caddy, nginx, or load balancer)
- [ ] Database backups are scheduled (or `BACKUP_SCHEDULE_ENABLED=true`), with `BACKUP_ENCRYPTION_KEY` and an offsite `BACKUP_S3_BUCKET` set
- [ ] `METRICS_TOKEN` is set so `/api/v1/metrics` is not publicly scrapable
- [ ] Health probes (`/api/v1/health/live` + `/ready`) are wired into your orchestrator — see [Monitoring](/deployment/monitoring)
- [ ] `ERROR_TRACKING_DSN` points at a self-hosted GlitchTip/Sentry (EU), if used
- [ ] Redis persistence is enabled (`appendonly yes`)
- [ ] MeiliSearch master key is set
- [ ] `MAIL_TRANSPORT=smtp` with valid SMTP credentials
- [ ] `MAIL_FROM` uses your domain (e.g. `noreply@yourdomain.com`)
- [ ] `MAIL_BASE_URL` matches your public Studio URL
- [ ] `FEDERATION_GATEWAY_URL` points to a secured gateway (HTTPS, not publicly reachable without auth)
- [ ] `FED_ADMIN_TOKEN` is a unique, random string (min 64 chars)
- [ ] `DISCOVERY_NODE_PUBLISHER_KEY` is set and registered on every Discovery Node you publish to
- [ ] `CONTEXT_DIRECTORY_SERVICE_KEY` is set to the same value as the Context Directory's `CD_SERVICE_KEY` (consumer features)
- [ ] `DISCOVER_DEBUG` is unset or `false`
- [ ] `CRASH_LOG_FILE` points at a persistent, writable path if you want a crash log next to your log shipping
